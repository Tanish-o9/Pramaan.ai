# pgvector 1:N Fast Biometric Vector Search in Pramaan

## 1. Architectural Overview
Prior to this release, biometric matching in Pramaan loaded all student embeddings into application RAM and evaluated pairwise Euclidean norms in an $O(N)$ Python loop. 

With **Feature 1**, Pramaan introduces native **PostgreSQL `pgvector`** integration. Embeddings are indexed directly inside the database using **Hierarchical Navigable Small World (HNSW)** vector graphs. Matching queries execute inside the database engine, cutting query latencies and scaling to tens of thousands of student biometric vectors.

---

## 2. Table Schema (`student_embeddings`)
Unlike the legacy `students.face_embedding` column which was limited to a single embedding per student, `student_embeddings` allows **multiple embeddings per student** (e.g., student with/without spectacles, varying lighting conditions, beard variations, or updated voice samples).

```sql
create table student_embeddings (
  id bigint generated by default as identity primary key,
  student_id bigint not null references students(student_id) on delete cascade,
  modality text not null check (modality in ('face', 'voice')),
  embedding vector(128),            -- 128-d dlib ResNet face descriptor
  voice_embedding vector(256),      -- 256-d Resemblyzer GE2E speaker descriptor
  quality float default 1.0,        -- Image/Audio quality metric (0.0 to 1.0)
  source text default 'web_registration',
  created_at timestamptz default now()
);
```

### Distance Operators & Indexing
* **Face Recognition (128-d):** Uses **L2 / Euclidean Distance (`<->`)**.
  ```sql
  create index idx_student_embeddings_face_hnsw 
    on student_embeddings using hnsw (embedding vector_l2_ops)
    with (m = 16, ef_construction = 64);
  ```
* **Voice Identification (256-d):** Uses **Cosine Distance (`<=>`)**.
  ```sql
  create index idx_student_embeddings_voice_hnsw 
    on student_embeddings using hnsw (voice_embedding vector_cosine_ops)
    with (m = 16, ef_construction = 64);
  ```

## 3. Subject-Scoped Enrollment Filtering
In an institution with 5,000 students, scanning every face against the entire university roster increases both latency and False Acceptance Rate (FAR).

Pramaan's SQL RPC (`match_face_embeddings`) accepts an optional `filter_subject_id`. When provided, the search space is immediately restricted to only the students enrolled in that specific lecture:
```sql
and (
  filter_subject_id is null
  or exists (
    select 1 from subject_students ss
    where ss.subject_id = filter_subject_id
      and ss.student_id = se.student_id
  )
)
```
This narrows the candidate vector pool from 5,000 down to ~60 students, yielding a **12x to 18x latency speedup** and eliminating cross-department false matches.

---

## 4. Margin Ambiguity Check (Anti-Lookalike Gating)
A critical vulnerability in 1:N biometric matching occurs when two different students (e.g. lookalikes, siblings, or twins) both fall within the global distance threshold (0.60).

Pramaan enforces a strict **Margin Check**:
$$\text{Margin} = \text{Distance}_{\text{second\_best}} - \text{Distance}_{\text{best}}$$
* If $\text{Margin} < \text{PGVECTOR\_MIN\_MARGIN}$ (default: `0.05`) between two different students, the match is rejected as **ambiguous** (`is_ambiguous: True`).
* The system refuses to guess, logs a warning, and flags the attendance record for faculty verification.

## 5. Performance Benchmarks

Measured on synthetic 128-d embeddings using `scripts/benchmark_pgvector.py`:

| Dataset Size | Matching Strategy | Latency p50 | Latency p95 | Search Space |
|---|---|---|---|---|
| **1,000 Vectors** | Full In-Memory Scan | 0.84 ms | 1.15 ms | 1,000 students |
| **1,000 Vectors** | **Subject-Scoped Scan (60 students)** | **0.06 ms** | **0.11 ms** | **60 students (16.6x faster)** |
| **10,000 Vectors**| Full In-Memory Scan | 8.21 ms | 11.45 ms | 10,000 students |
| **10,000 Vectors**| **pgvector HNSW (Database Index)** | **1.72 ms** | **2.35 ms** | **O(log N) hop traversal** |

## 6. Migration & Fallback Operations

### Executing Migration:
1. Apply the SQL migration in Supabase SQL editor:
   ```sql
   \i src/database/migrations/001_pgvector_setup.sql
   ```
2. Run the legacy migration script to copy existing single embeddings into `student_embeddings`:
   ```bash
   python scripts/migrate_to_pgvector.py
   ```

### Graceful Fallback:
If `ENABLE_PGVECTOR = False` or if PostgreSQL is unreachable or running without the `vector` extension, `VectorSearchService` automatically falls back to an in-memory subject-scoped numpy L2 matcher with the identical margin check and confidence formulas.
